# Пропан — @gazpropan_uz_bot

Бот шохобчалар, пропан нархлари ва усталар телефонлари каталогини кўрсатади.
Буюртма қабул қилмайди. SQLite каталог ва қайта ишланган хабар рақамини сақлайди.
Ҳақиқий маълумотлар ҳали берилмаган: дастлаб каталог бўш.

## Тайёр Windows дастурини олиш

1. GitHub репозиторийсида **Actions → Windows EXE** ни очинг.
2. Яшил белги билан тугаган охирги йиғишни очинг.
3. Пастда **Artifacts → PropanBot-Windows** ни босинг. GitHub аккаунтига кирган бўлишингиз керак.
4. Юкланган архивни очинг. Ичидаги `PropanBot-Windows.zip` ни ҳам очинг.
5. `PropanBot` папкасини оддий ёзиладиган жойга, масалан Documents ичига жойлаштиринг.
6. `START.bat` ни босинг. Биринчи марта `.env` файли яратилади ва Блокнотда очилади.
7. `TELEGRAM_BOT_TOKEN=` дан кейин BotFather берган токенни ёзинг. Сақланг ва Блокнотни ёпинг. Токенни чатга юборманг.
8. `START.bat` ни яна босинг. Telegram’да @gazpropan_uz_bot га `/start` юборинг.
9. Тўхтатиш учун `STOP.bat` ни босинг. 45 сониягача кутинг ёки бот ойнасида Ctrl+C босинг.

Windows 10/11 x64, интернет ва компьютернинг ёқилган ҳолатда туриши керак.
Python ўрнатиш шарт эмас. GitHub Actions ботни 24 соат ишлатмайди, фақат EXE йиғади.
Бир токен билан бошқа серверда ишлаётган бот бўлса, аввал уни тўхтатинг.
Агар webhook ёқилган бўлса, дастур уни ўзбошимчалик билан ўчирмайди.

## Файллар ва хавфсизлик

- `.env.example` — токенсиз намуна; `.env` — фақат ўз компьютерингиздаги сир.
- `data/propan.sqlite3` — биринчи ишга тушганда автоматик яратилади.
- `run/` — ботни тўхтатиш ва иккинчи нусха ишлашини чеклаш учун.
- `.gitignore` токен, сессия, базалар ва ишчи папкаларни Git’дан чиқаради.
- ZIP фақат EXE, икки BAT, токенсиз намуна, бўш каталог намунаси ва ушбу йўриқномадан йиғилади.
- Токен GitHub Secrets’га ҳам керак эмас: йиғиш ва тестлар токенсиз ўтади.
- `.gitignore` олдин юкланган сирларни ўчирмайди. `.env` ни ҳеч қачон `git add -f` билан қўшманг.

## Янги меню: бутун Ўзбекистон

`/start` юборилса, шохобчалар, нархлар, усталар телефонлари ва ҳудудлар тугмалари чиқади.
Буюртма қабул қилиш йўқ. `/regions` — 14 ҳудуд рўйхати.
Ҳудуд бўйича қидириш учун унинг номини ёзинг, масалан `Бухоро`.
`/stations Самарқанд`, `/prices Тошкент`, `/masters Андижон` буйруқлари ҳам ишлайди.
Ҳудуд номлари лотинда ёки кириллда қидирилади.
Жойлашув тугмаси маълумотлар базасидаги координатали шохобчаларни масофа бўйича саралайди.
Масофа йўл узунлиги эмас, тўғри чизиқ бўйича тахминий масофа. Фойдаланувчи жойлашуви сақланмайди.

### Ҳақиқий маълумотларни киритиш

Дастлаб каталог бўш: тасдиқланган манзил, нарх ва телефон рақамлари ҳали берилмаган.
Бот интернетдан нархларни автоматик олмайди. Маълумотни масъул шахс текшириб киритади.

1. `STOP.bat` орқали ботни тўхтатинг ва бот ойнаси ёпилишини кутинг.
2. `catalog.example.json` нусхасини шу папкада `catalog.json` деб сақланг.
3. Қуйидаги шаклда ўз маълумотингизни киритинг. Бу фақат шакл намунаси; қавс ичидаги матнларни алмаштиринг.

```json
{
  "stations": [
    {
      "id": "station-1",
      "name": "[Шохобчанинг ҳақиқий номи]",
      "region": "[Вилоят ва шаҳар ёки туман]",
      "address": "[Аниқ манзил]",
      "phone": "[Иш учун эълон қилинган телефон]",
      "price": null,
      "updated": "",
      "latitude": null,
      "longitude": null
    }
  ],
  "masters": [
    {
      "id": "master-1",
      "name": "[Уста ёки устахона номи]",
      "region": "[Вилоят ва шаҳар ёки туман]",
      "address": "[Устахона манзили]",
      "specialty": "[Қиладиган иши]",
      "phone": "[Иш учун эълон қилинган телефон]"
    }
  ]
}
```

Нарх маълум бўлса, `price` га бир литр учун бутун сўм миқдорини қўштирноқсиз ёзинг.
`updated` га шу нарх текширилган санани `YYYY-MM-DD` шаклида ёзинг. Келажак санаси қабул қилинмайди.
Координаталар маълум бўлса, `latitude` ва `longitude` га харитадаги сонларни ёзинг; бўлмаса `null` қолсин.
Ҳар бир ёзувнинг `id` қиймати ўз бўлимида такрорланмасин. Кейинги ёзувлар вергул билан ажратилади.
4. Файлни UTF-8 шаклида сақланг ва `START.bat` ни босинг.

`catalog.json` ҳар ишга тушганда SQLite каталогига ўқилади. Файлдаги рўйхат базадаги каталогни тўлиқ алмаштиради.
Хато файл қабул қилинмайди ва база ўзгармайди. Файл бўлмаса, базадаги каталог сақланади.
Каталог ва база GitHub'га ҳамда Actions архивига кирмайди. Шахсий телефонларни рухсатсиз киритманг.

### Янги версияга ўтиш

1. Эски ботни `STOP.bat` билан тўхтатиб, бот ойнаси ёпилишини кутинг.
2. Янги ZIP'ни алоҳида папкага очинг.
3. Эски папкадан `.env`, `data` папкаси ва мавжуд бўлса `catalog.json` ни янги папкага нусхаланг.
4. Янги папкада `START.bat` ни ишга туширинг. Telegram'да `/start` юборинг.
5. Эски ва янги ботни бир вақтда ишлатманг. Токенни қайта олиш шарт эмас.

## Иштирокчилар хабаридан автоматик янгилаш

Ягона манба — @propan_uzbekistan_2026 гуруҳи. Фақат шу гуруҳга келган янги хабарлар базани янгилайди.
Бошқа гуруҳлар ва шахсий хабарлар каталогни ўзгартирмайди; шахсий чатда қидирув ишлайди.
`/format` буйруғи керакли хабар шаклини кўрсатади. Бот матн ва расм остидаги матнни ўқийди;
расм ичидаги ёзув, овоз ва видеони ўқимайди. Ҳозирги ажратувчи аниқ белгиланган майдонлар билан ишлайди.
Эркин ёзилган ҳар қандай хабарни тушуниш кафолатланмайди.

Шохобча учун алоҳида хабар:

```text
Шохобча: [ҳақиқий номи]
Ҳудуд: [вилоят ва туман]
Манзил: [аниқ манзил]
Нарх: 6000 сўм
```

Уста учун алоҳида хабар:

```text
Уста: [уста ёки устахона номи]
Ҳудуд: [вилоят ва туман]
Манзил: [устахона манзили]
Хизмат: [хизмат тури]
Телефон: [иш учун эълон қилинган рақам]
```

Намуналардаги қавсларни ҳақиқий маълумотга алмаштиринг. 6000 фақат мисол нарх.
Майдон номларини лотинда ҳам ёзиш мумкин: Shoxobcha, Hudud, Manzil, Narx; Usta, Xizmat, Telefon.
Шохобча номи, ҳудуди ва манзили бир хил бўлса, янги хабар мавжуд ёзувни янгилайди.
Манзилсиз нарх янгилаш фақат шу ном ва ҳудудда битта ёзув топилганда қабул қилинади.
Ҳудуд ва номни ҳар сафар бир хил шаклда ёзиш керак; ҳар хил қисқартмалар алоҳида жой деб қабул қилиниши мумкин.
Такрор хабар қайта киритилмайди. Форвард қилинган хабарда Telegram берган асл сана ишлатилади;
эски хабар янги маълумотни босиб кетмайди. Сана ёки жой ноаниқ бўлса, база ўзгармайди.
Ноаниқ, лекин мавзуга тегишли хабарлар маҳаллий SQLite'да `inbox` жадвалида `review` ҳолатида сақланади.
Бот юборувчига сабабини айтади; тўғриланган хабарни қайта юбориш мумкин.
Бу хабарлар ҳам шахсий базанинг бир қисми ва GitHub ёки ZIP'га юкланмайди.
Иштирокчи берган маълумот мустақил тасдиқланган деб кўрсатилмайди.

### Гуруҳдан қабул қилиш

Гуруҳни ҳаволасини ёзишнинг ўзи хабар олиш учун етарли эмас.
Админ ботни гуруҳга қўшиши ва хабарларни ўқишга рухсат бериши керак.

Privacy ўзгарганда ботни гуруҳдан чиқариб қайта қўшиш талаб қилиниши мумкин.
Манба номи кодда қатъий белгиланган: `propan_uzbekistan_2026`. Гуруҳ ID киритиш талаб қилинмайди.
Гуруҳнинг @номи ўзгарса, қабул қилиш тўхтайди; коддаги манбани алоҳида ўзгартириш керак бўлади.
Бот саволларга гуруҳда жавоб беради. Гуруҳга ўзи қўшила олмайди, админ қўшиши керак.
Бот олдинги хабарлар тарихини ололмайди. Гуруҳга қўшилгандан ва рухсат берилгандан кейинги янги хабарларни қабул қилади.
Ботга шахсий юборилган аввалги 100 та хабар импорт қилинмайди: фақат белгиланган гуруҳ манба ҳисобланади.

Нарх сўралмаган хабарга жавобдаги оддий рақам нарх деб қабул қилинмайди.


## Асосий иш тартиби: савол ва жавоб гуруҳнинг ўзида

Иштирокчи @gazpropan_uz_bot шахсий чатига ўтиши шарт эмас.

Жой кўрсатилмаган бўлса, шу гуруҳда жой номини саволга қўшишни сўрайди.

## Сассу кўприк атрофидаги учта алоҳида шохобча

Фойдаланувчи берган мўлжаллар:
- 8-заправка — Сассу кўприкка етмасдан.
- 9-заправка — Сассу кўприкдан кейин.
- Кофе заправка / Қизил заправка — 9-заправканинг рўпарасидаги битта бошқа шохобча.

Сассу мост, Сассиқ мост, Сассу кўприк ва Сассиқ кўприк бир хил мўлжални билдиради.
Фақат кўприк номи айтилса, қайси шохобча экани сўралади; унинг нархи автоматик танланмайди.

Бу ёзув алмаштириш, бошқа тилга таржима эмас. Карточкани тугма билан янгилаганда унинг ёзуви сақланади.
Бот инсон жавобини 30 сония кутади. Аввалги 60 сониялик навбатлар янги версияда 30 сонияга мосланади.
Эски саволлар тарихини таҳлил қилиш ҳали ҳам гуруҳга жавоб юбормайди.

Карточка остида битта қаторда 3 та тугма:
- «💰 Нарх манбаси» — айнан нарх берилган хабар.
- «🟢 Ҳолат манбаси» — очиқ/ёпиқ ҳолат айтилган хабар.
- «📍 Мўлжал» — берилган локация ёки маълум мўлжал.

Нарх ва ҳолат турли хабарда бўлса, икки ҳавола ҳам алоҳида сақланади.
Манба ҳали йўқ бўлса, тугма «манба ҳали сақланмаган» деб маълумот беради, сохта ҳавола очмайди.
Эски «Манба», «Муаллиф», «Нарх», «Ҳолат», «Шохобчалар» тугмалари карточка остида кўрсатилмайди.
Шохобчалар рўйхати `/stations` билан очилади.
`/status` янги версияда `wait-30-uz` деб кўрсатади.

## Савол сўзида бир ҳарф тушиб қолиши

`mayorskida narx qnaqa` ҳам `qanaqa` каби нарх саволи деб қабул қилинади.
Савол ва сўровнинг кенг ишлатиладиган сўзларида бир ҳарф тушиши, алмашиши ёки ёнма-ён
ҳарф ўрни алмашиши ҳисобга олинади: qnaqa, qnacha, qacha, qnday, aytvorla.

Ҳар қандай эркин ёзилган саволни тушуниш кафолатланмайди.
`/status` янги версияда `wait-30-uz2` деб кўрсатади.

## Маҳаллий AI'ни 59 та ҳолатда автоматик синаш

Бу синов ҳозирги қоидали ботни AI билан автоматик алмаштирмайди. Аввал модель сифати баҳоланади.
Фойдаланувчи компьютерида Ollama ва `qwen2.5:3b` юкланган бўлиши керак.
Python, Telegram токени ва ташқи pullik API калити керак эмас.

1. Янги архивни алоҳида папкага очинг.
2. Ботни STOP.bat билан тўхтатиб, Ollama'ни ишлаб турган ҳолатда қолдиринг.
3. `AI_TEST.bat` ни икки марта босинг.
4. Ойнада 1/59 ... 59/59 тугагунча кутинг. Ҳар бир синов учун PASS/FAIL ва вақт кўрсатилади.
5. `ai-test-results/AI_TEST_RESULTS.json` файлини таҳлил учун чатга юборинг.

`AI_TEST_RESULTS.txt` инсон ўқиши учун қисқа натижа; JSON'да ҳар бир ҳақиқий модель жавоби,
кутилган жавоб, фарқланган майдонлар, тезлик ва модель параметрлари сақланади.
Ollama йўқ бўлса, `unavailable` деб ёзилади: модель синовдан ўтган деб кўрсатилмайди.
Синов тўхтатилса, олинган натижалар сақланади, лекин тугалланмаган деб белгиланади.
Синов бот базасини ўқимайди/ўзгартирмайди, Telegram'га хабар юбормайди.
Фақат маҳаллий `127.0.0.1:11434` га мурожаат қилади; шaxsiy гуруҳ экспорти эмас,
чатда берилган шохобча номлари ва сунъий мисоллар ишлатилади.
Натижа файллари GitHub ёки ZIP йиғишга киритилмайди.

59 ҳолат: аввалги 31 та сўров/нарх/ҳолат/Reply/ноаниқлик мисоли ва каталогнинг 28 та шохобчаси ҳақида саволлар.
Кутиладиган жавоблар модель сўровига юборилмайди; улар фақат баҳолашда ишлатилади.
Бу кичик мақсадли тўплам: 59/59 бўлса ҳам ҳар қандай эркин хабарда 100% аниқлик кафолати эмас.
Коднинг unit-тестлари модель сифати натижаси эмас; ҳақиқий сифат фақат компьютердаги модель жавобидан ҳисобланади.

## AI диагностика v2 — кейинги қадам

Аввалги 59 та синовда ҳозирги модель/сўров/формат бирикмаси ишончсиз натижа берди.
Сабабни ажратиш учун янги `AI_DIAG.bat` тайёрланган. Ҳақиқий натижа фақат Ollama ишлаётган компьютерда олинади.

1. Янги ZIP'ни алоҳида папкага очинг. Аввалги `AI_TEST_RESULTS.json` ни сақланг.
2. Ботни STOP.bat билан тўхтатинг, Ollama ишлаб турсин.
3. `AI_DIAG.bat` ни ишга тушириб, 32/32 тугашини кутинг.
4. `ai-test-results/AI_DIAG_RESULTS.json` файлини чатга юборинг.

12 та қисқа ҳолат: ниятни аниқлаш (4), фақат нархни олиш (4), фақат очиқ/ёпиқ ҳолатни олиш (4).
Ният ва нарх вазифалари оддий JSON ва типи аниқ JSON schema билан солиштирилади.
Ҳолат вазифаси 4 форматда солиштирилади: оддий JSON, аввалги услубдаги nullable enum,
типи аниқ string/null enum ва очиқ/ёпиқ/unknown (номаълум) қийматлари.
Жами 32 та модель сўрови. Ҳар сўровда фақат битта вазифа ва битта чиқиш майдони бор;
узун 31 та ном каталоги юборилмайди. Кутиладиган жавоблар модель сўровига қўшилмайди.
Бу кичик диагностика; яхшиланса ҳам тўлиқ гуруҳ сценарийлари алоҳида қайта текширилади.
Ботга AI ҳали автоматик уланмайди, база ўзгармайди, Telegram'га хабар юборилмайди.
Эски натижа файли алмаштирилмайди. Натижалар GitHub'га юкланмайди.
